# Introduction

Stage manages tasks, schedules, dependency trees and journals across T3 Code and OpenCode V2. Choose a harness per task. Open its session for questions and approvals. When execution finishes, review the bounded final reply and complete the task in Stage. A dependent in a manual tree becomes ready for you to start.

## Connect a harness

Open Settings to pair T3 or connect an existing OpenCode 2.3.0 service. For OpenCode on the Stage server's machine, click **Connect** (or run `stage opencode connect`); Stage signs in with the service's own password. For another machine, run `opencode pair` there and paste one link (or `stage opencode pair LINK`); Stage renews that session automatically. **Advanced** takes a plain service address. If your phone uses another address, set the browser service URL. If you use a separate web client, enter its URL and register the service in that browser once. Task detail also offers **Open on service** and **Copy session ID**.

Create a Stage project and bind its workspace on each harness you use. Select the destination on each new task when a project has both bindings. Planning and accepted-result handoff work with a disconnected predecessor.

## Requirements

- For execution, an existing T3 Code or OpenCode V2 service. Planning works offline.
- Linux or macOS (amd64 or arm64), installed per user without root ([Install](/docs/install)).
  - **Desktop app**: Linux with glibc, GTK 3 and WebKitGTK 4.1. Mac desktop releases ship only once they can be signed and notarized; until then use the headless install on a Mac.
  - **Headless server**: needs nothing else.
- Push notifications and installing the web app (PWA) need a secure context: `http://localhost` on the same machine, or HTTPS with a certificate your devices trust ([HTTPS and push notifications](/docs/deploy#https-and-push-notifications)).

## Security

:::warning
stage has no authentication. Anyone who can reach its listener can read tasks and journals, stop tasks, and launch agents in full-access mode on the host (`full-access` is the task default).
:::

- It listens on `127.0.0.1:7380` by default, or only on a private Unix socket (mode `0600`) when it runs as the per-user service.
- `/api` and `/mcp` reject requests browsers send on behalf of other sites (DNS rebinding, cross-site requests, form-encodable bodies). That policy is not authentication.
- Before exposing it to a network, put an authenticating HTTPS reverse proxy in front. A tailnet limits who can connect, not what they can do.

Details: [Security](/docs/deploy#security).

## How it is built

- **Server and CLI**: Go, one binary (`stage`). `stage` with no arguments or `stage serve` runs the server; other subcommands are the [agent CLI](/docs/agents) and management commands (`stage service`, `stage update`, `stage t3`).
- **Storage**: SQLite (`stage.db`) in the data dir: `$XDG_DATA_HOME/stage`, else `~/.local/share/stage` (macOS `~/Library/Application Support/stage`).
- **Web app**: React, served by the server, installable as a PWA with Web Push.
- **Desktop app**: the same UI in a native window. It bundles the CLI/server, starts the per-user service and connects over its Unix socket ([Desktop app](/docs/desktop)).
- **T3 integration**: T3's MCP endpoint (`T3_URL/mcp`), plus T3's OAuth and upload endpoints. stage polls active tasks every 5s, refreshes projects and tracked tasks every 5 min, and discovers active external sessions for notifications.
- **OpenCode integration**: V2 HTTP API for execution, workspace discovery and supported model and agent choices.
- **Agent interface**: the `stage` CLI, a stdio MCP server (`stage mcp`) and an HTTP MCP endpoint (`/mcp`), all over the server's REST API.
