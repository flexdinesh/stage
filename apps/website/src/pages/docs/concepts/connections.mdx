# Connections

Stage does not run agents itself. It hands each task to a **harness**, a service that runs coding agents, and follows the result. A **connection** is one harness service on one [machine](/docs/concepts/machines).

## Harnesses

| Harness | How Stage talks to it |
|---|---|
| T3 Code | T3's MCP endpoint, with T3's OAuth and upload endpoints |
| OpenCode V2 | OpenCode's V2 HTTP API (tested with 2.3.0) |
| Codex | The Codex app-server daemon on the computer where Stage runs |
| Claude Code | The `claude` command on the computer Stage runs on (background sessions) |

The harness keeps what it owns: models, workspaces and worktrees, conversations and its own UI. Stage keeps tasks, trees, journals, acceptance and handoff.

## One service, one machine

Each harness instance is its own connection: a T3 environment, an OpenCode service, a Codex home or a Claude Code config folder. A machine has at most one active connection per harness, so one T3, one OpenCode, one Codex and one Claude Code. With workers, each machine has its own.

## Connecting

A new install has no connections. Until one is set up, the Dashboard shows **Connect a harness**, which leads to Settings > Connections.

- **T3**: pair Stage with T3, in one click when T3 runs on the same machine, else with a code from `t3 pair`. T3 counts as connected only once paired; before that Stage never contacts it.
- **OpenCode**: click **Connect** for the service on the same machine, or paste an `opencode pair` link from another machine.
- **Codex**: click **Connect**. See [Codex](#codex).
- **Claude Code**: click **Connect**. Stage checks the `claude` command and Claude's own login. Only on the computer Stage runs on (the desktop app, or `stage serve --local-harnesses`); see the [Claude Code guide](/docs/guides/claude-code).

Setup details, addresses and tokens: [Connections reference](/docs/reference/connections).

## Codex

Codex runs only where Stage runs on your computer: the desktop app (or Stage's per-user service), or `stage serve --local-harnesses`. It is unavailable in the Docker image and on worker machines.

- **Connect**: click **Connect** in Settings > Connections, or run `stage harness codex run connect`. Stage uses `codex` on your PATH; set **Codex CLI** to a path to use another (`stage harness codex set binary=PATH`).
- **Signed out**: the panel shows the command that fixes it. Run `codex login`, then **Connect**. Stage stores no Codex credentials.
- **Daemon**: Stage starts the Codex app-server daemon on demand when it is down, and never stops, restarts or updates it. Running turns survive a Stage restart, and `codex resume` and Codex Desktop see the same threads.
- **Workspaces**: the projects Codex trusts. Trust a project in Codex; Stage never edits Codex's config. Tasks run in the project root, with no Codex worktrees and no Plan mode. Images are sent with the prompt. Permission: **Read only**, **Auto** (default) or **Full access**.
- **Questions and approvals**: answer them in Codex. A Codex task offers **Copy resume command** (`cd <dir> && codex resume <id>`) on its row and on task detail; run it in a terminal.
- **Tracking a session**: paste a thread id or a `codex resume <id>` command. Threads T3 Code started are refused: track them through T3.
- **Archive**: archiving a thread in Codex completes its task while **Complete tasks when archived in Codex** is on.
- **Disconnect**: `stage harness codex disconnect`, or Disconnect in Settings. Stage stops tracking; the daemon and its threads stay in Codex.

## Choosing a connection per task

Every task and schedule names its connection. Pick it on the task, or let it start on your default connection. Each connection keeps its own new-task defaults, such as a pinned model ([App reference](/docs/reference/app)).

## When a connection is offline

Stage and its harnesses fail independently.

- Planning works offline: create projects, tasks, trees and schedules with no harness connected.
- A lost connection preserves each task's state. Launches on it wait or are refused until it is back.
- A disconnected harness leaves the other harness, and planning, available.
- Accepted results are saved in Stage, so handoff to the next task works with the earlier task's harness offline.

The status button at the bottom of the sidebar sums up every connection on every machine. Click it for each one's state.

## Replacing a connection

Pairing a different T3, or confirming a different OpenCode service, retires the old connection. Its tasks stay as read-only history, unlaunched backlog tasks and schedules move to the new connection, and nothing is bound there until you rebind each project. Connecting the old instance again brings back its tasks and bindings.

## Auto-complete

A connection can complete a task for you. When a run succeeds and its T3 thread is settled, its OpenCode session or Codex thread archived, or its Claude Code session removed (`claude rm`), Stage accepts the task automatically, once per run, with that provenance shown. Failed or interrupted runs never auto-complete, and changing the task's state back undoes it. Auto-complete is on by default; turn it off per connection in its setup in Settings > Connections. See [Tasks](/docs/concepts/tasks) for completion.
