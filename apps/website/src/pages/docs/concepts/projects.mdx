# Projects

A project groups tasks, trees and schedules under one title. Stage owns its ID, title and archive state. Each **binding** points to a workspace on a [connection](/docs/concepts/connections).

## Stage owns the project

- Create a project with just a title. It needs no harness, so you can plan offline.
- Rename and archive it in Stage. A harness never renames or deletes it.
- If a workspace disappears or a harness is removed, the project keeps its tasks and history.

## Bindings

A workspace has one Stage owner. A project can have several workspaces
on a connection, with one primary. Tasks and schedules use that primary
by default. A task or schedule can use a specific binding through the CLI.

- **Bind workspace.** Pick an existing workspace the harness reports. To bind a directory the harness has yet to list, add it in the harness, then refresh workspaces.
- **Import.** Sync imports eligible workspaces. These include live T3 projects, unarchived OpenCode Git or Mercurial checkouts, Git checkouts Codex trusts, and Claude Code folders at a Git checkout's top.
- **Unbind.** Discovery records a decline for that workspace on its connection. Binding it manually clears the decline.

When a project has bindings on several connections, pick the connection for the new task.

## Paths change, history stays

Stage can carry a binding to a uniquely identified replacement workspace
on the same connection. When several replacements or source bindings
could match, the workspace waits for review. A chosen workspace that
becomes unavailable blocks launch. A claimed attempt keeps the destination
it used.

## Projects across machines

With [workers](/docs/concepts/machines), the same repository can be checked
out on several machines. A normalized Git origin and a known path within
the repository can join the same project across clones, worktrees and
machines. Each machine reads its own files. Directory and checkout keys
stay local to the file host. Pathless workspaces use their connection and
external ID. Several candidate projects require manual placement.

The CLI can merge projects and split a workspace into its own project.
A merged project's old ID still opens the surviving project.

## Archive

Archive and unarchive projects in Stage. A harness archive is stored as
workspace information. External removal preserves Stage tasks and history.

## Project scope

The sidebar lists projects with open work by recent activity, with counts for needs input, waiting on you and running. Pick one to scope Dashboard, Tasks, Trees and Schedules to it. Each device remembers the choice. Details: [App reference](/docs/reference/app).
