# Projects

A project groups tasks, trees and schedules under one title. Stage owns the project: its id, title and archive state. Where the code lives is a separate thing, a **binding** to a workspace on each [connection](/docs/concepts/connections).

## Stage owns the project

- Create a project with just a title. It needs no harness, so you can plan offline.
- Rename and archive it in Stage. A harness never renames or deletes it.
- If a workspace disappears or a harness is removed, the project keeps its tasks and history.

## Bindings

A binding ties a project to one workspace on one connection. A project has at most one binding per connection, and each workspace belongs to at most one project.

- **Bind workspace**: pick an existing workspace the harness reports. To bind a directory the harness does not list yet, add it in the harness, then refresh workspaces. Stage never creates harness projects, and never creates, clones or provisions directories.
- **Match**: Stage binds for you when the workspace is the project's only match: the same path on that machine, a checkout it can prove two harnesses share (through the shared path mappings you declare, or directly for Claude Code, Codex and a local OpenCode service), or the same Git remote and subproject on another machine. Other workspaces with the same Git remote only produce a suggestion you confirm.
- **Import**: each sync binds deliberate harness projects (live T3 projects, OpenCode Git or Mercurial checkouts it has not archived, Git checkouts Codex trusts, and Claude Code folders at a checkout's top). A workspace at a path a project already uses on that machine joins that project; a new path creates a project. The Projects page notes recent imports for 7 days.
- **Unbind**: unbinding declines that workspace for good. Discovery never binds it again until you bind it by hand.

When a project is bound on more than one connection, you pick the destination on each new task. The harness picker lists the project's bound connections first.

## Paths change, history stays

- If a bound workspace's path changes, Stage asks you to confirm it before launching there.
- Rebinding affects future launches only. Launches already started, and their history, stay attached to the workspace they used.

## Projects across machines

With [workers](/docs/concepts/machines), the same repository can be checked out on several machines. Each machine reads its own checkouts. A workspace on another machine joins the one project bound to the same Git origin remote and subproject. If more than one project could match, or the project already has another checkout on that machine, Stage waits for you to bind it by hand. A workspace with no remote never merges across machines.

## Archive

Your archive or unarchive decision sticks. A project discovery created, with no tasks, follows its workspace: it archives when the harness archives the workspace, until you decide yourself.

## Project scope

The sidebar lists projects with open work by recent activity, with counts for needs input, waiting on you and running. Pick one to scope Dashboard, Tasks, Trees and Schedules to it. Each device remembers the choice. Details: [App reference](/docs/reference/app).
