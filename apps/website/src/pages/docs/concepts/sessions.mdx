# Sessions and references

A **session** is the harness conversation behind a task: a T3 thread, an OpenCode session, a Codex thread or a Claude Code session. Stage starts a session when it launches a task and follows its state. The conversation itself, with its questions, approvals and detailed runs, stays in the harness.

## Work in the Session tab

Open a task's **Session** tab to answer a request or message the current session. Needs-input rows and notifications open this tab. **Requests** shows the questions and approvals Stage can answer. The composer offers **Send** after a turn ends, and **Steer** or **Queue** while a turn runs, according to the connection's capabilities. Where the harness exposes a native queue, **Queued messages** lets you cancel or steer a pending message.

| Harness | Answer in Stage | Message from Stage |
| --- | --- | --- |
| T3 Code | Questions | Send, Steer, Queue and manage pending messages when paired T3 advertises the tools |
| OpenCode | Permissions and supported forms | Send, Steer, Queue and manage pending messages with a compatible V2 service |
| Codex | Command, file-change and permission approvals on tracked active threads with a supported daemon | Send and Steer |
| Claude Code | Questions and approvals for sessions Stage starts with its hooks | Send between turns. Steer and Queue during a turn with Stage's versioned launch hooks |

T3 permissions, unsupported OpenCode forms, Codex questions and MCP prompts, and Claude Code requests without an active Stage hook are answered in the harness. **Open in T3** or **Open in OpenCode** uses the configured destination. For Codex and Claude Code, **Copy resume command** gives you the terminal command to open that session.

## Review attempts

The Session header lists recorded attempts newest first. Open an earlier attempt to inspect its read-only state, last reply and recent activity where available. **Last word** shows the latest cached assistant reply for the selected attempt, including while the harness is offline. **Recent activity** reads a bounded feed with plan steps and changed files when available. Open the harness for the full conversation. The Task tab holds the opening prompt, acceptance and journal.

## Tracking an existing session

You can adopt a session started directly in a harness as a task, so it shows in Stage and can be a node in a [tree](/docs/concepts/trees).

- Use **Track session** on the Dashboard, Tasks or Trees, or **Add session** in a tree.
- Choose the harness and paste the session link or id. Preview its title, project and state, then confirm with an optional title and initial note. The field's hint says what the harness accepts: for Codex, a thread id or a `codex resume <id>` command; for Claude Code, a session UUID, the 8-character ID `claude agents` shows, or a pasted `claude attach` or `--resume` command.
- Stage refuses a session another harness runs and tracks. A Codex thread or Claude Code session that T3 started is refused: track it through T3.
- Stage never starts the session. Its prompt is read from the harness, and Stop still works.
- A session already tracked returns its existing task. Subagent and archived sessions cannot be tracked.
- Tracking never completes the task, even for a finished session. You complete it, or the connection's auto-complete may on a later poll.

Agents can do the same for their own session, for example to queue work that runs after it ([Let agents manage work](/docs/guides/agents)).

## Linking an older launch

Stage reconciles unconfirmed launches by itself. For an older launch it cannot identify safely, use **Link existing session** on task detail: paste the session link, preview, then attach. Attaching launches no work.

## References

A reference is a link to a task, tree or session that you can paste into a prompt.

- **Copy link** in a task or tree header copies a self-describing markdown link, such as `[stage task #12: Title](…/tasks/12)` or `[stage tree #4: Title](…/trees/4)`. **URL** copies the bare link. Rows show a link icon on hover, and Alt C copies from the Ctrl K palette.
- An agent resolves a pasted link with `read_ref` or `stage show`. A task link returns the task and its session; a tree link returns the tree, ready for the tree tools.
- Pasted task and session links render as live chips (number or "session", title, state) in prompts, final replies and handoff text. Tree links stay plain links.

A reference is context only. It never creates a dependency: use [trees](/docs/concepts/trees) for that.
