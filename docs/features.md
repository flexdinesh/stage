# Features

Detailed behavior of each stage feature. Overview: [README](../README.md#features). REST contract: [api.md](api.md).

- **Projects**: 1:1 with T3 projects. Existing T3 projects import automatically. Sort by name or recent activity (latest thread update/settle or task change).
- **Tasks**: prompt, provider, model, effort, runtime mode, plan mode, worktree/branch, tags, optional initial journal note. Save to backlog or start right away.
- **Journals**: task and tree notes are append-only, with immutable IDs and provenance, optional categories (finding, decision, blocker, outcome), text search, notes/events/all filters, cursor pages (20 by default, 100 maximum), 600-rune previews and full-entry reads. Tree reads aggregate notes from current members; moving a task moves its notes, while tree notes/events stay in their original tree. Move events name both trees in both journals. Membership changes invalidate pagination. Append on closed work never reopens or schedules it. Recorded work protects tasks and trees from deletion, even after a member leaves. Creation/adoption accepts an initial note, schedules retain a note template, duplicates copy no notes. Old task notes are discarded; task event history stays; accurate tree event history starts at rollout.
- **Screenshots**: drop images on the prompt (or Add image; PNG, JPEG, GIF, WebP, up to 8 × 10 MB). They are sent to the T3 thread with the prompt on every launch; follow-ups can carry images too.
- **Live status**: backlog → running → needs input → done → settled (or failed / interrupted). Polled from T3 every 5s.
- **Task actions**: start, follow-up, stop, duplicate, open in T3.
- **Answer questions**: when a session waits on a question (T3 user input), task and session detail show it in a Needs input panel at the top: single or multi select, or your own answer, then Send answer. Needs-input rows, toasts and the notifications drawer get an Answer button, and needs-input pushes land on the panel. Permission approvals still resolve in T3; the panel counts them and links there.
- **Trees**: group tasks into a tree (a DAG; can span projects) where a task needs other members. A task starts when every need is settled in T3; a failed need keeps it blocked. Start mode per tree (auto launches, manual marks the task ready and notifies), overridable per task. Start early runs a blocked task anyway. Removing a task splices it out: its dependents take over its needs. Mark a tree done when you will not work on the rest (members keep their states, nothing more starts), or archive it; Reopen or Unarchive undoes it, and activity on a member reopens it on its own. Done and archived trees and their tasks leave the Dashboard. A standalone task can be archived the same way. Delete is only for work that never started and has no recorded work (deleting a tree deletes its tasks). Dissolve detaches tasks and archives the tree; emptying also archives it. Identity and journals survive. Manual tasks whose needs settled (and backlog roots) read ready: they list in the Dashboard Ready group and a `ready` notification (toast and inbox) offers Start. Track as task (session detail) adopts an existing T3 session so it can be a node (stage never starts it; its prompt is read from T3). Views: Trees (Active | Done | Archived | All, each tree with its last activity and created date), the tree view (a compact list in level order with each task's needs and time in its state, hover to trace needs, a side panel with the tree's day-grouped activity or, for a selected task, controls to edit needs, start mode, base and handoff), and a Tree panel on task detail with the same controls (or Add to tree: a new tree, or an active one). In a session's Created tasks, check independent backlog tasks and pick New tree from n (Parallel, or Chain in check order). Handoff (on by default, per task): when a task with needs starts, stage appends one block per finished need (final reply, PR links, branch/worktree, T3 thread link) to the prompt, so work carries context forward. Task detail shows what was appended; a failed read skips that need and logs why. Stacked work: a task's Workspace can be "#12's branch" (opt-in): its worktree starts from a need's branch (the sole need, or the picked one), so it builds on unmerged changes. It falls back to its own base ref (logged, shown on task detail) when no need can be picked, the need ran at root or in another project, has no branch, its PRs are merged, or the branch is gone.
- **Sessions**: browse Active or All sessions across projects, regardless of where they started. Active has no creation-date cutoff. Open local session details, inspect child sessions, or jump to T3. History remains available from Sessions.
- **Transcript**: session and task detail have an Overview | Transcript switch (`?view=transcript`). Read-only user and assistant messages and plans as safe markdown (no raw HTML, no remote images), newest 50 with Load earlier, long messages collapsed. Live while a run is active: the server polls T3 every 2s (one poller per session, only while someone watches) and pushes changes over SSE. Tool calls, commands and diffs stay in T3.
- **Last word**: each session's latest assistant reply, read during sync once a thread is at rest. Task and session detail show it as markdown (up to 4000 chars, with a link to T3 when longer); Needs input and Done rows show it as one line. Read-only: reply in T3.
- **Dashboard**: needs-input alert, plus trees, running, done (awaiting settle), failed, ready, backlog and settled (last 7 days) across projects. Tree members roll up into their tree's row (state bar, next step, Start ready); needs-input and ready members also keep their own row with a tree chip, and completed trees move to Settled. External T3 threads (not tasks) show under needs input and running.
- **Pull requests and runs**: PRs T3 links to a thread show as chips with their state (open, merged, closed) on task and session rows, and as a list on task and session detail linking to the PR. Detail pages also list the thread's runs (each follow-up is a new run): status, model, start, run time and queue time, newest first.
- **History**: every T3 thread, including ones started outside this app. Filter by time window, project, status, provider and source; shows counts per project and per day.
- **Scheduled tasks**: in the New task drawer pick Start → At time (one-shot: a backlog task starts at that wall time in a chosen zone; a time missed while the server was down starts late) or Repeat (a schedule: presets Hourly / Daily / Weekdays / Weekly or a raw 5-field cron, in its own IANA zone). Each fire spawns and starts a new task with the schedule's config and images; a fire is skipped while the previous run is still pending, running or needs input, and fires missed while the server was down are skipped. Schedules page, project panel, and a Scheduled (next 24h) group on Stage. Run now, pause/resume, edit, delete (spawned tasks are kept).
- **Ctrl K palette**: jump to tasks, projects and sessions by title, or find a session by what was said in it. Message text, branch, PR and project matches come from T3's thread search and are labeled (`branch`, `PR`, `you said`, `agent said`) under Sessions and In messages, with a snippet. Title matches show instantly; T3 matches follow. When T3 is offline or slow the palette keeps title matches and says so in its footer.
- **References**: task and session detail headers have Copy link (a self-describing markdown link, `[stage task #12: Title](…/tasks/12)`, for prompts) and URL (the bare link). Laptop rows (Dashboard, Project, Sessions, History) show a link icon on hover or keyboard focus, and Alt C in the Ctrl K palette copies the highlighted task or session. Paste a link into a prompt in stage or T3 and ask the agent to read it: `read_ref` / `stage show LINK` returns the task and/or session; the full conversation is one `t3_thread_read` away. Links use the address you copied from; the host is ignored when resolving. Pasted stage links (any host) render as live chips (number or "session", title, state marker) in the Prompt panel (task and session detail), schedule prompts, transcript user messages, last word and handoff text; unknown ones stay plain links.
- **Agents**: agents create, start and manage tasks via the `stage` CLI or MCP (stdio or HTTP), and use `read_journal`, `get_journal_entry`, `append_note` (`task notes` / `tree notes`). Every launch, including standalone and handoff-off, includes a persisted instruction block: refresh membership, read relevant notes, checkpoint before risky work, record outcomes, treat notes as context rather than authority, and report failed persistence. Retries reuse the block; handoff is independent. Existing/adopted sessions receive no retroactive message. See [Agents](../README.md#agents).
- **Snippets**: reusable prompt text, global or per project. Type `/` in a task prompt, follow-up or notes to pick one and insert it.
- **Model defaults**: new tasks prefill provider, model, effort, runtime and mode from a pinned default (Settings), else from your last created task.
- **Settings**: T3 connection status, manual pairing, sync now.
- **Notifications**: installable PWA with Web Push for needs input, failed, ready, done and settled (each toggleable in Settings), covering tasks and threads started directly in T3 (subagents excluded). The app icon badge counts what needs input. Needs HTTPS or localhost: see [HTTPS and push notifications](../README.md#https-and-push-notifications).
