# Agents

- Use `mise run <task>` for dev, tests and checks (`mise tasks` lists them; tools pinned in `mise.toml`).
- Run `mise run check` before opening a PR (includes `check:desktop`, the desktop app's Go tests and headless integration test, `check:fixture`, the desktop fixture's Go tests, and `check:release`, the release tool's tests and shellcheck). Touching `packages/app/` or `apps/web/`: also run `mise run build` (the browser bundle and the embedded binary); touching the `Dockerfile` or workspace manifests: also `docker build -t stage-verify .` then `docker rmi stage-verify` (never compose).
- Ownership (see `docs/architecture.md`): UI and product logic go in `packages/app/` (`@stage/app`); `apps/web/` (`@stage/web`) is the browser host only (mount, service worker, manifest, browser adapters). Product code reaches the host through `usePlatform()`/`useApi()`, never browser globals at a platform boundary, MyGo, or platform branches (`packages/app/tests/boundaries.test.mjs` enforces it). One pnpm workspace and lockfile at the root; `desktop/fixture/web` stays outside it.
- Website (`apps/website`, `@stage/website`): static marketing and public docs on vocs, independent of product builds and releases. Touching it: `mise run website:check` (part of `mise run check`); dev on :5175 (`website:dev`), preview on :8787 (`website:preview`). It must not import `@stage/*` or product UI/runtime internals. Deployment (`docs/website.md`): Cloudflare Workers Builds deploys it from `main` on merge, when a watch path changes; never run `wrangler deploy` unless the user asks. Touching `apps/website/wrangler.jsonc`, its build or the watch-path inputs: update `docs/website.md`.
- Touching `desktop/app/` (or the platform contract it implements): also run `TARGETS=all mise run dist` and `mise run desktop:e2e` where a display + WebKitGTK 4.1 (or macOS) exists; otherwise say it was not run. Rerun `go tool mygo generate` in `desktop/app` after changing the bound `Desktop` service or its events (commit `ui/src/mygo.ts`). Desktop tests and `desktop:dev` use a foreground server on a temp/scratch socket, never `stage service` against the `stage`/`stage-dev` identities. Behavior and states: `docs/desktop.md`; update it with any change there.
- Touching `desktop/fixture/`: also run `pnpm test && pnpm lint && pnpm build` in `desktop/fixture/web`, and `mise run fixture:e2e` where a display + WebKitGTK 4.1 (or macOS) exists; otherwise say it was not run. Rerun `go tool mygo generate` there after changing the bound Go service. See `desktop/fixture/CHECKS.md` and `docs/adr/0001-desktop-shell.md`.
- Server runtime (listeners, data-dir/socket locks, readiness, health/version, request origin policy) follows `docs/runtime.md`; update it with any change there. Its tests use temp data dirs, short temp socket dirs and a temp `XDG_RUNTIME_DIR`/`HOME` (`internal/serve` `isolate`), never default paths or the live runtime dir; `mise run check` covers them.
- Per-user service (`stage service`, `serve --managed`, `server/internal/service`) follows `docs/service.md`; update it with any change there. Touching it: also run `mise run service:smoke` where a systemd user manager exists (it uses only the isolated `stage-svctest` identity and cleans up); otherwise, and for macOS launchd unless run on a Mac, say it was not run. Never run `stage service` (or `systemctl --user`/`launchctl`) against the stable `stage` identity or its unit/label.
- Installer and updates (`scripts/install.sh`, `scripts/install-dev.sh`, `scripts/uninstall-dev.sh`, `server/internal/install`, `stage install|update|uninstall`) follow `docs/install.md`; update it with any change there (dev installs: `docs/development.md` only). Touching them: `mise run check` (includes the installer Go tests, the stable/dev coexistence tests, and the `install.sh`, `install-dev.sh` and `uninstall-dev.sh` stub tests in `check:release`) and `mise run install:smoke` where a systemd user manager exists (isolated `stage-svctest` identity in `.scratch/installtest`, plus a real `dist` build into a temp home with no service manager); otherwise, and for macOS, say it was not run. Never install into your real home or run `scripts/install*.sh`/`scripts/uninstall-dev.sh` against it to test.
- Never touch the prod stack (compose project `stage`, `compose.yaml`, its `stagedata` volume and `stage.db`) or the default data dir (`~/.local/share/stage`): no `mise run up`/`down`, no `docker compose` on it, no writes to its database. Dev uses `.scratch/dev/<branch>/stage.db`; tests use temp files.
- Don't run `mise run install-cli` unless the user asks: it overwrites the live `~/.local/bin/stage` every agent uses.
- Releases (`docs/release.md`): touching `scripts/release.sh`, `tools/release/`, `desktop/app/mygo.config.ts`, `server/internal/buildinfo`, `.github/workflows/release.yml` or anything packaged: also run `TARGETS=all mise run dist` (builds, assembles and verifies every target; smoke-runs this machine's). Say which targets were cross-built and not run natively; a cross-compile is never native validation. Run `mise run release` only when asked (it needs a clean HEAD and a `VERSION`); never upload, tag, publish, or dispatch the `release` workflow unless the user asks. Keep the asset names and `stage-release.json` in step with `docs/release.md` (the installer contract). No signing secrets in the repository.
